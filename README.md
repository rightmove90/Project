# بوابة المبيعات — نسخة GitHub Pages + Google Apps Script

- **الواجهة**: صفحات ثابتة تُستضاف مجاناً على GitHub Pages (دائمة، بلا خادم).
- **الخلفية**: سكربت Google Apps Script يعمل داخل حسابك على Google، يقرأ ويكتب في مجلد المشاريع في Drive ويدير المستخدمين.
- **البيانات**: كلها في Drive (المشاريع + ملفان صغيران `_portal_users.json` و`_portal_settings.json` في المجلد الرئيسي).

```
index.html  app.js  style.css  config.js     ← الواجهة (GitHub Pages)
share.html  share.js                         ← صفحة العميل (روابط المشاركة)
apps-script/Code.gs  appsscript.json         ← الخلفية (تُلصق في Apps Script)
test/                                        ← الاختبارات (اختيارية)
```

## الجزء 1: الخلفية على Google (10 دقائق)

1. في Drive أنشئ مجلداً رئيسياً (مثلاً «المشاريع») وانسخ معرّفه من الرابط: `drive.google.com/drive/folders/`**`المعرّف`**
2. افتح [script.google.com](https://script.google.com) ← **New project**.
3. احذف المحتوى الموجود في `Code.gs` والصق محتوى الملف `apps-script/Code.gs`.
4. من **Project Settings** (⚙️) فعّل **Show "appsscript.json" manifest file in editor**، ثم ارجع للمحرر وافتح `appsscript.json` واستبدل محتواه بمحتوى الملف المرفق.
5. في **Project Settings ← Script properties ← Add script property** أضف:
   | الاسم | القيمة |
   |---|---|
   | `ROOT_FOLDER_ID` | معرّف المجلد (أو رابطه كاملاً) |
   | `ADMIN_PASSWORD` | كلمة مرور المسؤول (6 أحرف فأكثر) |
   | `ADMIN_USERNAME` | اختياري، الافتراضي `admin` |
6. في المحرر اختر الدالة **`setup`** من القائمة أعلى الصفحة واضغط **Run**. وافق على الصلاحيات (قد تظهر «Google hasn't verified this app» ← **Advanced** ← **Go to ... (unsafe)** ← **Allow**؛ هذا سكربتك أنت). يظهر في **Execution log** أنه أُنشئ حساب المسؤول، وتُحذف `ADMIN_PASSWORD` تلقائياً.
   `setup` يضبط أيضاً مشاركة المجلد الرئيسي على «Anyone with the link — Viewer» ليستطيع العملاء فتح الملفات. إن منعت مؤسستك ذلك فاضبطه يدوياً.
7. **Deploy ← New deployment ← Select type ← Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
   ثم **Deploy** وانسخ **Web app URL** (ينتهي بـ `/exec`).

> **مهم:** كلما عدّلت `Code.gs` لاحقاً يجب **Deploy ← Manage deployments ← ✏️ ← Version: New version ← Deploy** وإلا يبقى الكود القديم يعمل. الرابط لا يتغير.

## الجزء 2: الواجهة على GitHub Pages

1. أنشئ مستودعاً جديداً على GitHub واجعله **Public** (GitHub Pages على المستودعات الخاصة يحتاج خطة مدفوعة). لا توجد أسرار في ملفات الواجهة: رابط الخلفية وحده لا يعطي صلاحية، فالدخول بكلمة مرور.
2. ارفع كل ملفات هذا المجلد (Add file ← Upload files، أو `git push`).
3. عدّل `config.js` وضع رابط الخلفية:
   ```js
   window.PORTAL = {
     API_URL: 'https://script.google.com/macros/s/AKfyc.../exec',
     MAX_UPLOAD_MB: 15
   };
   ```
4. **Settings ← Pages ← Source: Deploy from a branch ← Branch: `main` / `(root)` ← Save**.
5. بعد دقيقة يظهر الرابط: `https://اسم-حسابك.github.io/اسم-المستودع/` — افتحه وادخل بحساب المسؤول.

## الاستخدام

- **مشروع جديد**: زر «مشروع جديد» (للمسؤول) ينشئ المجلد وأقسامه في Drive.
- **الملفات**: «رفع ملفات» أو السحب والإفلات (حتى 15 MB للملف). **للملفات الأكبر (الفيديوهات خصوصاً)** ارفعها مباشرة في Drive داخل مجلد القسم، وتظهر بعد تحديث الصفحة (زر ⟳).
- بنية المجلدات: `المشاريع / اسم المشروع / info_ar · info_ku · info_en · videos · maps · location · prices` وصورة غلاف باسم `cover.jpg`.
- روابط يوتيوب/الخرائط: زر «إضافة رابط».
- **المستخدمون وأسماء الأقسام**: من «الإدارة». إيقاف الحساب يطرد الموظف فوراً.

## واتساب

- **على الهاتف**: «إرسال» يجهّز **الملف نفسه** ويفتح نافذة المشاركة؛ تختار واتساب ثم العميل. للقسم أو المشروع تُرسل عدة ملفات معاً.
- **الحد**: الإرسال المباشر للملفات حتى **10 MB** للملف. الأكبر (الفيديوهات غالباً) يُرسل **رابط Drive** تلقائياً.
- على الحاسوب غالباً تُرسل روابط. زر «إرسال: ملف/رابط» يبدّل الطريقة.
- صفحة المشروع للعميل: `share.html?t=...` (رابط موقّع، بلا تسجيل دخول).

## الصيانة (دوال تُشغَّل من محرر Apps Script)

| الدالة | متى |
|---|---|
| `resetAdminPassword()` | نسيت كلمة مرور المسؤول: ضع `ADMIN_USERNAME` و`ADMIN_PASSWORD` في الخصائص ثم شغّلها |
| `rotateSecret()` | لإبطال كل الجلسات وروابط صفحات المشاركة المرسلة سابقاً |
| `setup()` | آمنة لإعادة التشغيل |

لرؤية سبب أي خطأ في الخادم: أضف خاصية `DEBUG` بقيمة `1`، وراجع **Executions** في Apps Script.

## حدود هذه المعمارية (قارن بنسخة Node)

- **الحجم**: رفع حتى 15 MB من الموقع، وإرسال مباشر حتى 10 MB. هذه حدود Apps Script والمتصفح.
- **الروابط**: ملفات المشروع تُفتح عبر روابط Drive المشتركة «لكل من لديه الرابط». من وصله رابط ملف يبقى يفتحه حتى بعد إيقاف حسابه؛ لإبطال ذلك غيّر مشاركة المجلد في Drive.
- **السرعة**: أول فتح لمشروع قد يستغرق 2–5 ثوانٍ (Drive عبر Apps Script)، ثم يُخزَّن 2 دقيقة.
- **الحصص**: لحساب Gmail المجاني حدود يومية لـ Apps Script (كافية لفريق مبيعات عادي).
- **كلمات المرور**: مجزّأة بـ SHA-256 مكرر مع ملح، أضعف من scrypt المستخدم في نسخة Node.
- حساب Google Workspace قد يمنع نشر Web app لـ «Anyone»؛ جرّب بحساب شخصي أو اطلب من مسؤول النطاق السماح.

## الاختبار

```
node test/backend.test.js     # الخلفية على بيئة Apps Script محاكاة
python3 test/e2e.py           # الواجهة في متصفح (يحتاج playwright)
```
المحاكاة لا تعوّض التجربة الحقيقية على Google: تحقق بعد النشر من الدخول ثم رفع ملف ثم الإرسال.
